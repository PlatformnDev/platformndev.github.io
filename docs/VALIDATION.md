# 검증 기록

검증일: 2026-09-18. 환경: Apple M5, 메모리 16GB, macOS arm64, Google Chrome 152.0.7977.82. Playwright로 실제 설치된 Chrome을 실행했습니다. 로컬 정적 빌드와 개발 서버를 별도로 확인했습니다.

## 통과한 검증

- 정적 빌드 및 기본 테스트 7개 통과. 파일 시그니처, 크기 제한 경계, PNG big-endian 크기, AVIF ispe 크기, 파일명, 알파 합성, 마스크 정규화를 검증했습니다.
- JPG, PNG, WebP, AVIF, BMP, GIF 6종을 실제 모델로 처리하고 브라우저 다운로드 파일을 다시 디코딩했습니다. 모든 출력은 320×320 PNG이며 배경 픽셀의 알파가 0까지 내려갔습니다.
- 0/128 알파를 가진 입력은 결과에서도 각 알파 상한이 유지됐습니다.
- EXIF orientation=6인 80×40 JPEG가 40×80으로 돌아가며 위·아래 색 영역도 일치했습니다.
- 2프레임 GIF와 WebP를 서로 다른 시점에 각 3회 열어 항상 첫 프레임인 빨간색을 얻었습니다. APNG·움직이는 AVIF의 실제 파일 검증은 하지 않았습니다.
- 손상·제외 형식, 용량 초과 오류 후 정상 파일 처리, 추론 중 취소 후 다른 파일 처리에 성공했습니다.
- 모델 요청을 차단한 실패 후 동일 화면의 재시도가 성공했습니다. Worker의 Cache.put이 QuotaExceededError를 던지는 환경에서도 처리했습니다.
- WebGPU 실제 실행, WASM 단일 스레드 강제 실행, WebGPU 초기화가 실패하도록 만든 환경에서 WASM 자동 대체를 각각 확인했습니다.
- 5,000×5,000(25MP) JPEG를 실제 처리하고 같은 크기의 PNG로 다운로드했습니다. WebGPU에서 다운로드 완료까지 2.51초였습니다. 여러 파일을 동시에 드롭하면 한 장씩 선택하라는 안내가 나타났습니다.
- 연속 10개 이미지 처리에서 살아 있는 Worker는 1개, DOM 노드는 128~130개, 이벤트 리스너는 33개로 유지됐습니다. GC 후 메인 페이지 JS heap은 약 2.17MB로 안정적이었습니다. GPU·WASM 내부 할당 전체를 계측한 결과는 아니므로 메모리 누수가 전혀 없다는 보장은 아닙니다.
- 20회 실제 이미지 처리 중 기록된 요청 76건은 모두 동일 출처의 GET이었습니다. 업로드 요청, 이미지·파일명이 담긴 요청 본문, 외부 출처 요청이 없었습니다.
- 배포용 CSP를 적용한 프로덕션 페이지에서 실제 처리가 성공했고 정책 위반이 없었습니다.
- 390px 모바일 폭에서 가로 넘침이 없음을 확인했습니다. 실제 모바일 기기에서 모델을 실행한 검증은 아닙니다.
- 선택적 WebMCP 상태 조회·취소·잘못된 입력 거부는 등록 인터페이스를 모사한 harness로 확인했습니다. 이후 Codex 인앱 브라우저에서도 실제 등록된 상태 조회, 진행 중 작업 취소, 빈 작업 취소 오류, 잘못된 입력 거부를 확인했습니다.

## 로컬 성능

시간은 네트워크 속도가 빠른 localhost에서 측정했으며 공개 사이트의 첫 다운로드 시간을 의미하지 않습니다.

| 실행 조건 | 전체 | 모델 읽기·준비 | 추론·합성·PNG 생성 |
|---|---:|---:|---:|
| WebGPU, 새 브라우저 컨텍스트 | 1.56초 | 1.10초 | 0.44초 |
| WebGPU, 같은 세션 재사용 | 0.29초 | 0.00초 | 0.28초 |
| WebGPU, 페이지 새로고침 후 모델 캐시 | 0.86초 | 0.53초 | 0.32초 |
| WASM, 첫 전체 처리 | 7.64초 | 별도 구분 없이 UI 기준 | 전체 시간에 포함 |
| WASM, 반복 전체 처리 | 주로 5.8~6.7초 | 세션 재사용 | 전체 시간에 포함 |

WebGPU 새 컨텍스트에서 모델 조각 읽기와 검증은 0.58초, 새로고침 후 캐시 읽기는 0.14초였습니다. 초기 병렬 검증 중에는 WebGPU 추론이 1.11초까지 측정됐습니다. 모델 입력은 항상 1024×1024이고 출력 해상도에 따라 합성 시간과 메모리가 달라집니다.

샘플 출처는 `scripts/prepare-samples.mjs`에 고정되어 있습니다. 결과는 로컬 `test-results/quality-contact-sheet.png`와 각 PNG에 남겼으며 사이트에는 게시하지 않습니다.

## 검증 범위의 한계

- Edge는 현재 환경에 설치되어 있지 않아 실제 검증하지 못했습니다. Chrome과 같은 계열이라는 이유로 통과했다고 표시하지 않습니다.
- Safari·Firefox·실제 모바일 기기 검증은 하지 않았습니다. Chrome 버전은 설치본 번호이며 공개 배포 채널의 최신 버전 여부를 별도 확인하지 않았습니다.
- 실제 메모리 부족 상황의 강제 재현은 미실시입니다. 제한 경계와 오류 처리는 코드·기본 테스트로 검증했습니다.
- 애니메이션 AVIF/APNG는 추가 수동 검증 대상입니다.
- 공개 배포와 로그인 없는 세션 검증은 배포 이후 수행하며, 최종 전달 메시지와 로컬 `test-results/`에 결과를 남깁니다.

## MLB 사용 예시 추가 검증

오타니 쇼헤이 사진(David, CC BY 2.0)을 596×1200 JPEG로 제공했습니다. 인앱 브라우저에서 예시 버튼 → 실제 모델 배경 제거 → 투명 PNG 다운로드 링크 표시를 확인했습니다. 선수와 배트는 유지되며 배경은 제거됩니다. 앞쪽 포수의 일부가 희미하게 남는 품질 한계가 있어 수동 검수가 필요합니다. 세로 사진의 미리보기가 잘리는 CSS 문제를 수정하고 전체 사진 표시를 확인했습니다. 사진 출처와 라이선스는 화면 및 `public/examples/ATTRIBUTION.md`에 기록했습니다.

## GitHub Pages 이전 준비 검증

`SITE_BASE_PATH=/remove-bg/`로 정적 빌드 후 인앱 브라우저에서 예시 사진의 배경 제거를 확인했습니다. 기본 처리 및 `?engine=wasm` 두 경로 모두 원본 크기의 결과와 다운로드 링크를 표시했고 콘솔 오류는 없었습니다. 모델·WASM·예시 사진·라이선스 링크가 프로젝트 하위 경로를 사용합니다. Node 기본 테스트 7개와 TypeScript 빌드가 통과했습니다. GitHub 원격 배포 검증은 저장소 선택 이후 진행합니다.
